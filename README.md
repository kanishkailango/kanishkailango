# 🏗️ Project Architecture

I am interested in understanding how individual technologies work together to form a complete application.

A typical database-driven application separates its responsibilities into layers.

| Layer | Responsibility | Example technologies |
|---|---|---|
| Presentation | Collect input and display results | HTML, CSS, JavaScript |
| API | Receive and respond to HTTP requests | Flask |
| Application logic | Validate requests and apply rules | Python |
| Data access | Execute database operations | SQL |
| Database | Store structured records | PostgreSQL |
| Analytics | Transform data into useful findings | Python, SQL, Power BI |
| Version control | Track source code changes | Git, GitHub |

### Why This Separation Matters

- **Maintainability:** Each component has a defined responsibility.
- **Reusability:** APIs can serve multiple interfaces.
- **Testability:** Individual components can be tested independently.
- **Scalability:** Components can evolve as requirements change.
- **Security:** Validation and access control can be implemented at appropriate boundaries.

This is a general architecture pattern, not a claim that every project in this profile already implements all these layers.

# 🐍 GitHub Contribution Snake

<div align="center">

<img
  src="https://raw.githubusercontent.com/YOUR_USERNAME/YOUR_USERNAME/output/github-contribution-snake.svg"
  alt="GitHub contribution snake animation"
  width="100%"

</div>

### Setup instructions

Create `.github/workflows/snake.yml` in your profile repository and add:

```yaml
name: Generate Contribution Snake

on:
  schedule:
    - cron: "0 0 * * *"
  workflow_dispatch:

permissions:
  contents: write

jobs:
  generate:
    runs-on: ubuntu-latest

    steps:
      - name: Generate snake
        uses: Platane/snk/svg-only@v3
        with:
          github_user_name: YOUR_USERNAME
          outputs: dist/github-contribution-snake.svg

      - name: Publish snake
        uses: peaceiris/actions-gh-pages@v4
        with:
          publish_branch: output
          publish_dir: dist
          github_token: ${{ secrets.GITHUB_TOKEN }}
```

Replace `YOUR_USERNAME` in the workflow with your actual GitHub username. Commit the file, then open **Actions** and manually run the workflow. Confirm that the run succeeds and the `output` branch contains `github-contribution-snake.svg`.

# 🧠 My Problem-Solving Approach

I aim to approach technical problems systematically rather than immediately jumping to a solution.

**1. Understand:** Define the problem and expected outcome.

**2. Investigate:** Examine available data, code, logs, or error messages.

**3. Break down:** Divide the problem into smaller components.

**4. Design:** Select a suitable approach and identify trade-offs.

**5. Implement:** Build the solution in manageable steps.

**6. Test:** Verify normal cases, edge cases, and failure scenarios.

**7. Explain:** Document the result, limitations, and important decisions.

**8. Improve:** Use feedback and testing to refine the solution.

### Principles I Value

- Clear and readable code.
- Accurate data and calculations.
- Consistent database operations.
- Meaningful error messages.
- Reusable components.
- Proper documentation.
- Evidence-based conclusions.
- Continuous improvement.
